Two structural problems fall out of that table:

1. **The patch stack's maintenance cost is dominated by noise.** 54% of the diff is mechanical `#include` insertion. It is also the part that breaks on every WPE bump, and it drowns the ~50 patches that carry actual behaviour.
2. **The project's most valuable knowledge is not in git.** The benchmarking traps, device recipes and the 1,279-line investigation log live only in `/root` on this host. A reinstall loses them.

## A. Patch stack

### A1. Replace the portability patches with a forced-include prelude (biggest single win)
Delete ~25 patches / ~13k lines by moving the mechanical includes into the build:
- add `-include cstdint -include cstddef -include span` to `CMAKE_CXX_FLAGS` in `sfos-toolchain*.cmake`;
- for `wtf/Platform.h` / `wtf/ExportMacros.h`, prefer a generated prelude header force-included per target that already has the WTF include dirs, since third-party targets (Skia, ANGLE) do not.

Cheapest disproof, in order: (1) grep whether any of the 1,045 sites is in a target lacking WTF include dirs — minutes; (2) one CI build with the std-header preludes only — the flags are additive, so a failure names the offender. Fallback if force-includes prove unworkable: keep the patches but **generate** them (`scripts/gen-portability-patch.py` re-derives the insertions from a compile-error sweep), so a version bump costs a rerun instead of fixing 1,045 hunks by hand.

Expected effect: patch count 117 → ~92, diff 24k → ~11k lines, and the bump procedure's "validate the stack sequentially" step stops being the dominant cost.

### A2. Squash the per-subsystem families
Nine patches editing one file means every bump replays nine ordering constraints. Now that the scroll-tier ladder, tile-upload and composite patches are shipped default-ON and device-validated, collapse each family into one patch per subsystem (`atlantic-scroll-tier.patch`, `atlantic-tile-upload.patch`, `atlantic-composite.patch`). Keep single-purpose patches separate only while their default is still OFF or unverified — that is the property that justifies isolation, not authorship order.

### A3. Generated series table — first half done
`patches/SERIES.md` now exists, generated by `scripts/gen-patch-series.py` from the apply order in `patches.sh` (117 patches, 42 portability / 75 behaviour, 1,311 files, 95 flags, plus the hot-file ordering constraints). Still to do: add `default` / `status` / `verified build` columns, which need the tunables table from B1, and give CI something to check against it.

### A4. Retire dead weight
- Consolidate the four diagnostics patches (`paint-log`, `scrolltier-log`, `tile-raster-cost-instrumentation`, `frame-trace`) into one `atlantic-diagnostics.patch`.
- Re-bench or revert the patches already recorded as inert (`webkit-style-smart-reconstruct` is byte-identical on CNN; the Skia MSAA/glyph-cache knobs measure zero outside canvas). Per the project's own rule: add a deliberately generous third arm; if all arms are flat, revert rather than keep on faith.

## B. Runtime configuration

### B1. One declarative tunables table
Today a value can be defined in the C++ fallback, in the wrapper, or in both with different numbers (`120/800/200` shipped vs `400/2500/300` in `CoordinatedBackingStoreProxy.cpp`), and one shipped comment contradicts the line below it. Introduce `config/tunables.toml` — name, default, owning patch, status (`experimental` / `shipped-on` / `inert`), verified build, one-line rationale — and generate from it: the wrapper's export block (via the existing `write-runtime-env.py`), `docs/TUNABLES.md`, and the A/B harness's arm definitions.

### B2. CI consistency check
Fail the build when a `WEBKIT_*`/`ATLANTIC_*` referenced in `patches/` has no table entry, or a table entry references no patch. That is what currently lets 41 flags exist with no documented default.

### B3. Flag lifecycle
Promote flags whose default has held for several builds (bake the default in C++, drop the wrapper line and the gate); revert the inert ones. Target 97 → ~40. Add `atldbg doctor --tunables` to print declared-vs-effective for the live process, so the README's `/proc/PID/environ` check becomes one command.

- tunables ↔ patches consistency (B2);
- RPM spec file list vs staged files, catching the "qmake INSTALLS never runs, data files must be `cp`'d" class of bug;
- `shellcheck` on `runtime-common.sh` and the build scripts.
